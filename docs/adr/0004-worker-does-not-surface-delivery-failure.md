# 工作机不提示报警送达失败

报警上报失败时，工作机只写一行日志（`DouyinPopupAlarmService` 的错误分支），界面上没有任何提示；设置页那条警告只在服务器地址为空时出现，地址填了但服务器关机、IP 变更、防火墙拦截、网络中断一律无提示。本机语音兜底已在早期移除，因此也没有声音。我们**有意接受**这一静默失效，不做界面指示、不加本机语音兜底：靠人定期查看报警服务器托盘上的活跃列表。

## 后果

- 存在一个完整的无声失效场景：验证弹窗挡住中控台、直播停摆、报警服务器一片安静、工作机屏幕一切正常，无人知晓。
- 这比不部署本系统更危险：不部署时人知道要盯屏幕；部署并信任它之后，人不再盯了。本决策把"有意识的警惕"换成了"依赖一条无人监督的链路"。
- 下游没有任何告警，因此**弹窗检测本身的准确性成为唯一防线**——漏检等于完全失声。见 `CONTEXT.md` 中"验证弹窗"的定义。
- 曾考虑的两个方案：工作机常驻界面显示"报警未送达"红色指示（连续失败 3 次即 15 秒后亮起）；或上报连续失败时退回本机 `System.Speech` 播报。两者都被否决，理由是接受现状的成本为零。
- 重开本决策的信号：出现过一次因送达失败而无人知晓的弹窗。届时首选界面指示——它不依赖工作机有音箱，也不撤销"语音归服务器"的决定。
